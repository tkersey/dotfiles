# Selected workflow and catalog probes

Use when changing descriptions, progressive disclosure, observation authority,
or the affected cross-skill boundaries. These are authoring/evaluation cases,
not runtime gates, mandatory task reports, or a new test framework. Run only the
cases relevant to the changed contract and report which were actually observed.
Existing package/native tests retain their authority; these cases do not replace
them or establish model efficacy by their presence in a file.

## Evaluation setup

Bind baseline/candidate package identities and the actual installed catalog when
accessible, including system skills and the surrounding AGENTS instructions.
Keep model/version, reasoning configuration, task/evidence inputs and authorized
effects fixed except the declared treatment. Record unavailable runtime/catalog
access; repository descriptions alone cannot prove rendered catalog truncation.

For a relocation, check selected-reference reachability and preservation of the
source obligations first. Then observe activation, loaded resources, consequential
decisions and outcome separately. Test nearby descriptions together: a skill may
be good in isolation and misroute in the full catalog. Stable doctrine passages,
contract IDs, custody definitions and production review counts remain protected.
Use the existing [agent-performance](agent-performance.md) measurement discipline
and package/cognitive probes, not a script that grades prose as behavior.

## Resumption and steering

Use existing working facts, source locations and owner receipts, not a new
compaction schema or store. In a matched continuation case, compact or interrupt
only through supported runtime behavior and then inspect the actual recovery.

Retain accepted requirements/non-goals, current authority, exact base/head,
selected route, unresolved accepted evidence, proof applicability and public-effect
state. A summary is navigation, never a replacement for source authority or an
unrecoverable CAS receipt. Missing evidence limits the dependent claim.

Exercise three distinct changes: (1) an unrelated concurrent edit, (2) a relevant
head/requirement change, and (3) a substantive discussion update without a head
change. Reconcile the first without clobbering, refresh bindings and invalidate
dependent proof/credit for the second, and reassess findings against the current
discussion for the third. Do not replay completed publication or capture merely
because context was compacted. Do not preserve stale credit or launch a duplicate
architecture/review pass merely because the summary omitted its owner facts.

A new user constraint changes the next dependent action, not already-executed
history. Continue independent authorized work while the dependent boundary is
unresolved. Observe that the final report preserves real limitations rather than
claiming completion from a compacted narrative.
