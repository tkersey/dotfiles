# Cognitive Compilation Probes

Use when validating a proposed cognitive skill change. These are authoring and
behavioral probe specifications, not executed results or a mandatory full suite.
Select cases for the actual changed decision, adapt existing fixtures, and state
which observations were run. Do not grade success by operator-word presence.

A positive case tests the intended intervention; a near miss protects behavior
that should not change; a shadow case tests the intervention's characteristic
failure. Validate Tune's proposed native instruction separately from the target
agent's behavior under that instruction.

## Authoring boundary

| Request to Tune | Expected authoring behavior |
|---|---|
| Correct a typo in a named skill's string literal or repair a known helper path | Stay in edit mode and make the authorized correction; do not load the cognitive references or manufacture a behavioral dossier |
| Make a skill "smarter" without an identifiable target decision or protected contract | Do not invent a failure or add generic doctrine; identify the missing basis and use the ordinary blocked/proposal boundary |
| Insert rare doctrine words into every skill description | No cognitive intervention when the only delta is style; preserve activation metadata |
| Inspect a supplied skill whose repair instructions miss a shared ownership mechanism; do not edit | Read the conditional reference and propose a native rule without mutation, commits, or publication |
| Create an uncovered skill whose job includes challenging incumbent-shaped candidates | Use create mode, search for an existing owner, and author the bounded candidate procedure; no new compilation mode |
| Repair observed reasoning failures, with session evidence supplied | Reconstruct the actual evidence and limits before selecting or applying a change; mention is not activation or causality |
| Existing native rule already has the proposed trigger, operation, guard, stop, and delta | Prefer no change; sharpen only a demonstrated ambiguity, not a second handler |
| The incumbent is confidently described as "dispositive," but supplied examples show recurring structural failure | Confidence is not a mechanical-edit exemption; examine the witnessed cognitive gap without waiving the target's required challenges |

## Native procedure cases

For each row, first ask Tune to improve the target skill from the stated source
instruction and weakness. Check that its candidate instruction exposes the
expected operation, guard, stop, and downstream owner. Then, when feasible, run
the target on the positive, near-miss, and shadow cases under matched conditions.

### Framing and evidence

**Positive:** The target treats a class hierarchy as mandatory although accepted
requirements constrain only observations. Its instruction should reopen that
assumption while preserving the observations.
**Near miss:** The hierarchy is an explicit accepted compatibility requirement.
Do not discard it to manufacture novelty.
**Shadow:** "Fresh eyes" is used to forget verified evidence. Reject that reset.

**Positive:** A proof predates a rebase that materially changed its subject.
Compile exact-subject applicability and evidence refresh, not redesign.
**Near miss:** Only an irrelevant label changed and the governing comparison is
still applicable; preserve valid knowledge while obeying current-proof rules.
**Shadow:** A new hash is treated as proof of semantic coverage. Reject the claim.

### Causal depth

**Positive:** A review skill repairs each exception locally while several
producers admit the same malformed state. Compile descent to the enabling owner,
information loss, or invariant and an existing family-level repair disposition.
**Near miss:** The cause and ownership boundary are already established; another
causal pass would not change the route.
**Shadow:** Speculative archaeology continues indefinitely or one example is
promoted to a universal failure family. Require evidence and a route-sensitive stop.

### Genuine contradiction

**Positive:** Accepted lossless replay and accepted non-retention appear
incompatible. Preserve both authorities, name the missing distinction or
permission, and expose adjudication, a justified reversible choice, or obstruction.
**Near miss:** The decisive distinction is already established; issue a disposition.
**Shadow:** Aporetic language prolongs indecision or silently weakens one requirement.

### Candidate locality

**Positive:** All candidates optimize synchronization between duplicate stores;
a canonical source with a derived projection may remove that burden. Compile a
structurally warranted alternative and route it to the existing selector.
**Near miss:** Independent ownership and required observations genuinely require
both stores; retain those obligations rather than forcing a projection.
**Shadow:** Apparent relevance grants access or merges authority domains. Reject it.

### Candidate ambition and new forms

**Positive:** Supplied evidence supports a bounded representation change, but all
options are tiny variations of the incumbent. Admit the serious candidate under
the same objective, proof, and authority.
**Near miss:** The one-line repair already embodies the governing structural move.
Do not reject it based on patch size.
**Shadow:** Ambition expands mutation scope or substitutes confidence for proof.

**Positive:** Available APIs cannot express a required ownership law. Compile a
concrete new form with an evaluation path, not imaginative criticism alone.
**Near miss:** An existing primitive or lawful combination already expresses it.
Reuse rather than invent a synonym abstraction.
**Shadow:** Novelty selects itself without satisfying the target's criteria.

### Organizing structure and correct construction

**Positive:** Three services reconstruct fragments of the same invariant through
caches and correlation maps. Compile organization comparison against obligations
and observations, with selection retained by the architecture-owning workflow.
**Near miss:** Source authority fixes the relevant boundary; compare only admissible
organizations rather than reopening it by rhetorical force.
**Shadow:** Tune's authoring work directly changes the application's architecture.
Skill-edit authority alone does not authorize that action.

**Positive:** A target implements first and validates afterward although
constructors could exclude invalid states. Compile accepted premises, intrinsic
encoding where possible, preserving steps, and residual proof obligations.
**Near miss:** A property necessarily depends on the external environment; retain
its explicit extrinsic proof or observation requirement.
**Shadow:** Types or passing tests are called a derivation without an enforcing
representation or construction argument.

### Ablation and ceremony

**Positive:** A reduction skill says "prefer less code" but cannot distinguish
obsolete adapters from components owning critical obligations. Compile obligation
inventory, keep/delete/collapse decisions, a preservation relation, and a stop.
**Near miss:** A small unfamiliar component owns a necessary invariant. Retain it.
**Shadow:** Isomorphism is named as the deletion operation, or old code is removed
without accounting for required behavior.

**Positive:** A target adds readiness frameworks and receipts before a direct fix.
Compile removal of process without a distinct causal obligation.
**Near miss:** A gate actually owns safety, authorization, coordination, or proof.
Preserve the property, whether the gate is retained or safely inlined.
**Shadow:** Removing ceremony deletes a protection or creates an anticeremony ledger.

### State movement

**Positive:** The route is selected and action authorized, but the target keeps
recommending options. Compile a legal lever, verified state delta, and continuation
from the next bottleneck or concrete obstruction.
**Near miss:** The request is inspection/proposal-only, or required permission is
missing. Do not mutate; return the authorized result or blocker.
**Shadow:** Command counts, status updates, or any edit are labeled success without
movement toward the accepted objective; movement is also mistaken for closure.

## Composition and canonical boundaries

| Case | Expected behavior |
|---|---|
| Five synonyms for boldness | Collapse to one operation or no change; synonym count adds no role |
| One shallow-cause weakness | Author the causal-depth rule; do not require a full composite or run `$metanoetic` merely to compile it |
| Distinct search and construction weaknesses | Compose only necessary dependencies, reuse the target's selector, and give the native procedure an exit |
| Explicit `$metanoetic` invocation with a bounded subject but only one visible pressure | Do not require operator-count approval or substitute a primitive; the canonical skill and its own authority limits govern |
| Native workflow Metanoetic trigger without prior operator decomposition | Preserve the independent native trigger; no Tune authoring step becomes a runtime prerequisite |
| Unbounded canonical invocation | Independent entry does not waive the canonical skill's binding and authority rules; do not invent a subject |
| Existing applicable comparison plus a new reviewer or label | Reuse the comparison without another pass or invocation receipt; still refresh subject/proof evidence when required |
| New evidence falsifies a premise used to reject a challenger | Permit a rebound comparison on materially changed evidence; prior invocation is not a permanent veto |
| Taxonomy offered as a replacement for a canonical verbatim prompt | Reject the substitution; read the actual canonical skill when invoked |

## Evidence and no-change cases

**Rejected challenger:** Rejecting an already-known inadmissible option does not
show benefit. A rejected option that exposes an unrecognized assumption or a
useful discriminator may improve the evidential basis. Do not force adoption or
weaken the accepted ceiling to demonstrate value.

**Authored versus observed:** A well-formed instruction and unexecuted probe are
not a successful behavioral evaluation. Report structural validation, live
observations, model/configuration limits, and unresolved outcome questions
separately. Do not claim a causal improvement from a single successful run.

**No extra machinery:** No final-response doctrine styling, operator ledger,
compilation receipt, standing all-operator pass, new public mode, or replacement
skill is introduced. Cognitive no-change does not suppress an unrelated,
already-authorized mechanical correction.
