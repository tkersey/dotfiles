# Challenge Contract

Run exactly one strongest challenge tied to the primary invariant.

Valid outcomes:

```text
pass
changed_architecture
changed_proof
changed_scope
changed_risk
preference_only
skipped
```

When architecture or abstraction is consequential, challenge the governing
organization rather than merely the proposed implementation. Ask the strongest
project-specific version of:

```text
Does the ordinary candidate already satisfy the law?
Could restricting the admitted domain remove the complexity?
Would a stronger representation or owner eliminate downstream validation?
Is truth duplicated across owners or encodings?
Does the design forget information that later work reconstructs?
Does every retained abstraction own a distinct live obligation?
Can observationally indistinguishable factors be quotiented?
Does the migration preserve required observations and retire the old factors?
Does the specification square commute under the declared equivalence?
```

A `changed_architecture` result must name the affected architectonic seam and every
downstream implementation-spec section derived from it. Revise only those sections,
then rerun the affected and downstream phases.

Challenge independence is valuable; broad review churn is not.
