# Review composition

Use only for a non-native review-bearing route. Native `review=actuating`
delegates to the actual installed Actuating contract without importing this
round count, selectors, report shape or scheduling.

## Bind the subject and selected contract

Resolve operation, strategy, workflow, subject, scope, effects and scheduling
before launching work. For combined/Elenctic assessment, resolve the exact unique
OPEN PR by its supplied selector; never substitute the current branch. For bare
implementation, run Actuating `implement` to local completion and use Ship to
publish the actual candidate before PR-only review. A publication restriction or
missing PR blocks that stage, not independent local implementation. Never create a
PR solely for an unrequested read-only assessment.

Architectonic-only `review` retains repository/subsystem/design subjects and its
own exact document/commit/working-content bindings. Do not invent a PR or merge
verdict for those subjects. Non-native implementation closeout is PR-bound; a
local-only user limit stops at the truthful local boundary, not closed-out PR work.

For a PR round retain the actual host/repository/PR, base tip, review merge base,
head/tree, accepted Goal, authorized path and proof scope, model/reasoning settings,
and selected installed policy identities. Base tip and merge base are distinct.
Recheck the complete changed-file inventory and relevant integration evidence.
Actuating's exact-head proof acceptance includes checking removed/weakened/skipped
verification against its still-required obligations before reviewability.

Freeze the selected owner policies for the run through their native mechanisms:
Elenctic's immutable policy snapshot/seed and Architectonic's actually read policy
bytes/identities. Reuse the intact bound versions for confirmation rounds; do not
mix an updated installed policy into existing credit. A missing old version or
explicit policy change requires rebinding and resets the affected strategy's credit.
An unchanged snapshot survives an installation update; provenance is not efficacy.

## Ordered assessment round

Allocate a real opaque round ID in the existing working set. Record the actual
owner output/attempt references as they exist, never placeholders represented as
completed reviews. Open the freeze when the first selected assessment starts.

1. **Architectonic**, when selected: invoke its installed public assessment on
   the exact PR and accepted scope. Use its reconstruction, obligation assignment,
   constructive challenge and interaction reconciliation. Preserve defects, risks,
   opportunities, preservation judgments and unresolved premises. Universalist
   remains an evidence-gated nomination owned by that reviewer, not an extra lane.
2. **Elenctic**, when selected: after Architectonic's selected runnable assessment
   and required continuations finish, recheck the same subject. Invoke its public
   campaign with `selection=all-changed`, `workflow=comments`, no GitHub mutations
   and deferred presentation under its
   [composition contract](../../elenctic/references/ergasterion-composition.md). Review-only
   Elenctic delegation can retain an explicitly requested `selection=unchecked`;
   closeout and combined review always require all-changed coverage.
3. **Aggregate** under [aggregation.md](aggregation.md). Include both complete
   source outputs, incomplete-source evidence/gaps and material current discussions,
   not only drafts or the latest favorable verdict. Close the evidence cut only
   after selected runnable work and required request-local recovery terminate and
   the joint fold is complete.

No source or successor mutation, experiments, commits, push or repair between
steps. A supported material Architectonic finding invalidates clean credit but
normally does not skip Elenctic: finish the pair for evidence on that same head.
An obstruction can leave one assessment incomplete; still perform independent
selected work when safely possible and preserve its evidence. Caller stop, changed
subject or real dependent capability failure is not a clean round. Never wait on
nonexistent work or retry an unchanged external blocker indefinitely.

Give Elenctic the same source-grounded objective and candidate, not an instruction
to confirm Architectonic. Keep the first verdict out of the second's initial
orientation where feasible. Share indispensable factual discoveries with attribution
and revalidation, then reconcile findings after both; disclose shared context rather
than calling correlated reviewers independent evidence. Elenctic's own prepared
seed and direct-child provenance requirements still apply.

An external head/base/Goal/proof/scope change stops stale launches and writes.
Safely finish/cancel or isolate already-live work under its owner's recovery rules;
retain historical evidence without current credit. Rebind and start a new round
only after no old worker can act against a mutable successor. A new head does not
erase an accepted liability. Recheck material discussion changes before aggregation
and delivery; a fixed commit alone does not freeze discussion evidence.

## Scheduling without changing meaning

With no explicit scheduling flag, preserve each selected reviewer's native
execution options: Architectonic may investigate directly or use supported prepared
parallelism; Elenctic uses its bounded native-fork window (default/cap 20).

Explicit `parallel-reviews` requires the selected reviewer's supported parallel
route, not overlapping the two stages. An unmet explicit topology requirement
remains an execution limitation; do not relabel direct work as parallel completion.
`serial-reviews` selects Architectonic direct investigation and Elenctic concurrency
one, retaining all preparation, scope, policy and provenance obligations. Concurrency
one is not a local-file fallback or permission to omit selected files. Reject an
explicit conflicting concurrency value before launch. Do not copy native Actuating
auxiliaries into this strategy: the reviewers already own their engineering concerns.

Preserve actual model and reasoning parity with construction, or the caller's
explicit reviewed configuration for a review-only task. Read realized runtime facts;
requested settings alone do not prove parity. Native task completion/provenance comes
from the actual runtime/owner. Do not invent CAS semantic receipts for Architectonic
or count an Elenctic campaign as a Codex native standard review.

## Credit and closeout

A one-shot `review` stops after its selected assessment and delivery. In closeout,
record `credit | hold | invalidated` and a short evidence basis for each distinct
round in the existing working set. Missing disposition means hold.

Credit requires all of:

- the complete required owner assessments on this exact candidate and policy;
- full selected scope, relevant integration and exposed cross-source obligations
  reconciled; combined/Elenctic closeout requires whole-PR coverage, not merely
  unchecked-selected coverage;
- no current accepted required liability, unresolved mandatory proof, unauthorized
  strengthening, or decision-limiting evidence gap;
- current source, verifier, review provenance and discussion facts supporting the
  claimed scope, not merely `APPROVE`, process success or an empty finding list.

For a reported limitation use Actuating's evidence-adequacy distinctions: recover
the missing observation/reasoning, identify exact current coverage, justify actual
nonapplicability without weakening the obligation, or hold. These semantic tests
are reused; the resulting credit is Ergasterion's, not a native receipt mutation.
Supported optional architectural opportunities and nonmandatory follow-ups remain
visible and do not reset or block a clean round. A risk is not accepted by its label;
required owner decisions remain unresolved until actually authorized.

The initial credited round counts as one. Run four additional distinct complete
rounds serially, each with fresh owner investigations, source output identities and
Elenctic campaign/seed/assignments when selected. Reuse immutable source facts and fixtures, not
old verdicts, copied investigations or a favorable prior review as confirmation.
Within a round, continue an incomplete assignment under its original identity;
a continuation is not another round. Complete blocked results are never retried
merely for approval. The new fresh round is an explicit Ergasterion confirmation
request, not Elenctic's own retry policy or a fix loop inside either reviewer.

A hold pauses new confirmations while recoverable work completes. Material accepted
findings, correctness-bearing candidate changes, changed accepted requirements,
base/integration context, review scope or selected policy reset the whole streak.
Strategy changes reset it as well; never convert native, architectural or Elenctic
counts into composite credit. Changed optional presentation alone grants no new credit
and does not erase evidence. Later contradictory evidence reopens affected prior
adjudications; final closure uses the complete current evidence, not just the last
five labels. Five clean rounds are bounded falsification evidence, not soundness proof.

## Realize one supported successor

After the entire invalidated round's evidence cut closes, pass the complete admitted
basis, counterevidence, Goal and unchanged obligations to Actuating `implement`.
Use its causal construction selection, recurrence handling and exact-head proof,
not a patch queue or bare Actuating invocation. Its local completion returns to
Ergasterion; it does not claim native review convergence. Review Fold capture is
conditional on actual enclosing authority and remains owned by its native writer.

Retire displaced compensators, migrate sanctioned paths and preserve required-valid
behavior under Actuating's existing obligations. A reviewer-suggested architecture
is a candidate, not adopted authority. No mandatory local-patch-first attempt or
compulsory rewrite exists. Finish the authorized objective rather than stopping
at the first fixed finding. Unresolved or refuted allegations are not fix commands.

Revalidate the actual successor, use Ship to update/publish the exact candidate,
and restart the full selected strategy at round one. Never review an intermediate
experiment or claim an unpushed local head matches the PR. Do not change model,
proof thresholds, scope, Goal, selection or acceptance criteria to protect a streak.

## Final closure and resume

After five credited rounds on unchanged inputs, refresh accepted obligations,
required proof, provider head/base/state and material discussions. Fold newly live
findings before completion. Use Ship's current exact-tuple proof/readback for any
required update or promotion; a metadata-only update cannot replace review or change
candidate identity. No merge is authorized. Complete only with all Goal deliverables,
proof obligations, accepted liabilities and required public facts resolved.

For Ergasterion-owned publication, use Ship's direct pull-request route with the
actual Git/validation facts. Do not manufacture an Actuating handoff, native review
contract or closure receipt. The native strategy retains its normal Actuating→Ship
composition.

A report artifact failure is a presentation limitation, not a code defect or a
silent excuse to omit the aggregate. A mandated missing deliverable still prevents
claiming that deliverable complete. Publish an honestly bounded interim result when
a concrete blocker or caller limit prevents required continuation.

On resume, recover the exact operation/strategy/round and direct owner attempts,
then use each owner's resume procedure. Preserve completed current assignments;
continue only unfinished work. Missing source identities grant no historical credit.
A changed subject begins a new round/handling namespace with revalidated historical
findings. No new durable journal or fixed retry/fix-iteration limit is introduced.
