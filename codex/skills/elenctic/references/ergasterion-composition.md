# Explicit selection and enclosing composition

Read before campaign preflight for explicit `selection=all-changed` or an accepted
Ergasterion handoff. This is Elenctic's owner-approved exception to the default
unchecked-file partition and standalone presentation boundary in campaign.md.
All other campaign, worker, engineering, authority and provenance requirements
remain in force. It creates no new worker or native review-credit kind.

## Selection is independent of Viewed

Bind `selection=unchecked | all-changed` in the existing campaign working set at
the initial complete inventory cut. Absence means `unchecked`, including legacy
campaigns. Resolve it independently from workflow and the actual PR selector.

| Selection | Frozen selected set | Frozen excluded set |
|---|---|---|
| `unchecked` | Every path whose initial state is not VIEWED | Initially VIEWED paths |
| `all-changed` | Every path in the complete current PR changed-file inventory | Empty |

For all-changed, campaign.md's references to selected-as-unchecked and pre-Viewed
exclusions use this explicit partition instead. Retain the original Viewed map
as observed UI state, not review evidence or a selection filter. Never unmark
files to manufacture work. Renames, deletions, generated/binary paths and causal
unchanged dependencies retain their existing treatment; none silently disappears.
Whole-PR credit still requires complete admitted evidence and reconciled material
interactions, never merely an empty exclusion set.

Freeze the selected mode/partition in the brief, canonical assignments and final
coverage note alongside existing policy/context/campaign identities. The fresh
campaign instance and selected digest remain real; no worker-v1 identity extension
or invented receipt is necessary. Resume the original partition, not current
checkboxes. Changing selection requires explicit new-cut authority, a new campaign
instance/preparation and revalidation; output-workflow switching alone cannot do it.
An empty changed inventory does not supply a vacuous approval or a confirmation.

`for construction` still does not request fresh review. A selection argument alone
cannot turn feedback-only analysis into a new campaign; only explicit fresh-review
intent or the enclosing round's explicit assessment request does so.

## Ergasterion invocation

An explicit Ergasterion operation selecting Elenctic is a deliberate invocation of
this explicit-only sibling. It does not enable implicit invocation generally.
The coordinator invokes the public Elenctic campaign, never its worker as a
replacement for preflight, preparation or reconciliation.

A combined or closeout handoff carries the exact PR/epoch and accepted obligations,
`selection=all-changed`, comments workflow, scheduling/model settings, **no GitHub
mutations**, and deferred presentation. This narrower effect scope disables Viewed
projection and own-root thread resolution, not complete discussion discovery,
substantive counter-case adjudication, inspection or required snapshot/seed work.
Record those writes as intentionally not attempted, not successful or failed.
Workers stay read-only. A no-file limit still prevents policy-snapshot creation;
report the actual dependent incompleteness rather than substituting a generic worker.

Elenctic runs exactly one campaign per requested round, finishes runnable selected
work, and returns its original full findings, adjudications, source identities,
coverage, policy/context/seed provenance and verdict. It does not run Actuating,
implement fixes, start confirmation rounds or confer native Actuating credit.
Ergasterion alone can request a later distinct campaign under its own policy.
Continue incomplete assignments under their original identity; never retry a
complete blocked assessment merely to obtain approval.

The first Architectonic assessment is not a verdict Elenctic must confirm. Shared
facts are attributed orientation, with normal source revalidation. Preserve the
actual preparation/history contract and do not inject later aggregate results into
the frozen seed. Independent source standards remain mandatory.

## Deferred output, not lost output

Only an explicit enclosing Ergasterion handoff may defer automatic rendering and
resolution/construction synthesis. Return the complete sanitized report and valid
native presentation input to that caller, with stable source findings and the
actual Elenctic identity. Do not render a fake aggregate Elenctic report or silently
remove original findings. Standalone selection=all-changed still renders normally.

The enclosing coordinator owns one joint fold and, if requested, one synthesis over
all source findings under its own report identity. Elenctic's source report remains
recoverable and its verdict/coverage unchanged by aggregation. Use the shared
renderer's explicit `ergasterion-report/v1` presentation route only for the actual
composition; it grants no Elenctic file coverage, native credit or action authority.
A caller-delivery failure preserves the source text and identifies the gap.
