# Offline auxiliary discovery comparison

Use only when auditing or tuning the lenses. These fixtures do not enter ordinary
Actuating review, add a lane, or change review credit. They test discovery without
a supplied allegation; Review Fold's admission fixtures test a different operation.

```bash
node codex/skills/actuating/tests/test-auxiliary-discovery.mjs
node codex/skills/actuating/tests/test-auxiliary-discovery.mjs --list
node codex/skills/actuating/tests/test-auxiliary-discovery.mjs --case subject-03
node codex/skills/actuating/tests/test-auxiliary-discovery.mjs --key
```

The ordinary test executes the checked-in synthetic probes and checks export
isolation. It does not run a model or decide the semantic truth of model findings.
The evaluator key includes six matched pairs and controls for independent oracles,
source-level structural obligations, legitimate guards, and missing authority.
Its `primary_lens` is an expected contribution, not an exclusive assignment.
`evidence-gap` is an evaluation expectation, not a new runtime review status.

For a model comparison, give each fresh reviewer only the selected exact lens
instructions and an individual `--case` export. Do not expose this document, the
script, evaluator key, probe, paired subject, expected verdict, or another
reviewer's output. The source deliberately fits in the supplied input. A run
with access to the answer key is contaminated, not held out. Expected observations
and allegations are absent from exports; reviewers must discover their own tests
or source traces. No production effects or unsafe experiments are required.

Compare old and revised prompts under the same model, reasoning/resource budget,
and subject bytes, using independent contexts and repeated runs. Vary case order;
do not always give defects before their controls. Evaluate every lens over the
same subjects to reveal overlap rather than hard-code ownership. Keep authoritative
facts available to all while preventing interpretation leakage. Native/default
standard comparisons must remain actual uncustomized reviews against equivalent
source-bound repository fixtures; do not call a custom prompt a native review.

Have an evaluator inspect each report against source and authority, using the key
as a reference rather than a substitute for adjudicating unexpected valid findings.
Measure genuine defect discovery, false findings on controls, correct uncertainty,
new independent witnesses beyond the other lenses, and downstream adjudication
cost separately. Track all original reports, not only the admitted corpus. Neither
low acceptance nor high raw finding count establishes improvement. Duplicates can
corroborate a defect but do not create independent witnesses or coverage.

## Native format and incomplete-evidence regression

Use `subject-16` as the missing-premise case for each of the four revised lenses.
Grade the native object separately from its evidence strength: an empty `findings`
array and `overall_correctness: "patch is correct"` must retain the unavailable
reservation contract in `overall_explanation`, without inventing a defect, location,
or proof of at-most-once behavior. Bare `clean` is not a native review object.

In a separate Actuating continuation, supply that report and its original subject
as owner evidence under the same Goal. The evaluator must check that the dependent
safety/closure claim remains unestablished, while independent authorized work may
continue. Neither a clean status nor a low confidence score discharges the missing
premise. Do not turn the limitation into a production repair or a new review status.
Use `subject-06` as a supported-preservation control; do not manufacture a blocker
when source and the other required owner evidence establish the obligation.

These are evaluator instructions, not worker context. A formatting-only probe or
a source-contract test does not establish that this continuation behaves correctly;
record live reviewer and continuation outcomes separately when actually run.

Treat these small subjects as discriminators, not representative efficacy proof.
Confirm promising changes with existing matched-snapshot offline audits of real
work, including omitted behavior, temporal failures, genuinely local defects, and
adequate incumbents. Measure unnecessary production changes as well as missed
failures. Add no runtime score, workflow store, or automatic acceptance classifier.
