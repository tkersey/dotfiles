# Reduced construction guidance: offline comparison

Status: **authored, not model-replayed**. No arm has been run by authoring this
file or passing the package tests. This is evaluator-only development guidance,
not a new Actuating route, runtime stage, delivery gate, or authorization to spend
money, install tools, disclose data, or change production review policy.

## Question and frozen subjects

Does reduced construction choreography improve first implementations and first
repairs, or preserve their quality with less total work? Test against both the
accumulated guidance and a baseline without the construction protocol. Smaller
instructions are the intervention, not the success criterion.

| Arm | Construction instructions | Result |
|---|---|---|
| A: accumulated | Dotfiles `5159d76f3b627fb334e2ecb89c5cccf1db9d2e07`, including its Actuating/Universalist composition and inherited instructions. | Not run. |
| B: reduced | The exact candidate commit containing this file; bind that commit and every loaded source before starting. | Not run. |
| C: protocol-free | The same task, hard constraints, authority, tools, knowledge access, and acceptance obligations, without Actuating's construction guidance or construction-skill orchestration wrappers. | Not run. |

Bind immutable repository and task snapshots, model/version, reasoning effort,
tool permissions, context settings, and resource ceilings. Use fresh independent
sessions and worktrees; a full-history fork is not context isolation. All arms
receive the same required behavior and deciding domain, not a preferred design.
The baseline's absence of a construction protocol does not waive source binding,
witness admission, independent verification, required-valid behavior, proof scope,
read-only/effect limits, or completion requirements.

Keep the knowledge available. Use the same source documentation and theory
reference whitelist in all arms. Separate task/domain knowledge from instructions
that prescribe a construction workflow; do not give C the protocol again through
a renamed reference, nor remove relevant mathematics only from C. Freeze and
inspect the common knowledge material before the run. If that separation cannot
be established, mark the comparison confounded rather than treating it as a
clean ablation. Reference access is an affordance; differing use may be an outcome.

For this comparison, B's Actuating-specific presentation override is bound to
`actuating-construction-core-v21` and its exact loaded adapter bytes. It changes
no standalone Universalist route or serialization contract. Preserve the original
attribution of every historical receipt and result.

## Prevent instruction and solution leakage

Audit the actual visible sources, not only the intended skill path: global and
repository `AGENTS.md`, skill metadata/default prompts, linked references,
Universalist adapters, automatic skill injection, memory, compaction summaries,
parent transcripts, and subagent inheritance. Retain source identities and the
observable delivered instructions through the existing evaluation evidence.
Do not collect or infer private reasoning traces. File-read counts do not prove
that a model followed an instruction.

C must not regain the removed protocol through a global mandate or a helper.
A and B must not inherit each other's candidate files or summaries. Do not silently
substitute a different model, effort level, permissions, or resource ceiling.
If a harness cannot enforce the assigned context, report the failure and its
consequence rather than credit the run as matched evidence.

Keep later fixes, this protocol, expected constructions, withheld tests, and grading
notes out of implementation contexts. Historical examples disclosed in the skills
or prior analysis are calibration material, not untouched holdouts. Porting an old
failure must not import its later repair. Preserve contemporaneous evidence when
it legitimately supports an incumbent; do not manufacture blindness by censoring
necessary facts.

## Tasks, runs, and freezing

Select untouched tasks across materially different domains, such as recursive
encoding, temporal/resource behavior, and query or transformation algorithms.
Include both initial implementation and repair, plus adequate-incumbent, direct-fix,
false-allegation, and wrong-oracle controls. Do not select only tasks whose desired
answer is a shared owner, tagged union, reducer, larger rewrite, or any other pattern.
Use an independent source-derived evaluator, not the candidate implementation, to
establish expected behavior and required-valid controls.

Choose sample size, independent repetitions, budget, and stopping rules before
seeing candidate outcomes. Randomize or counterbalance arm order. Preserve all
attempts, timeouts, failed invocations, incomplete results, and test failures; do
not rerun selectively until a preferred arm wins. A small pilot can establish
feasibility without supporting a general adoption claim. This document supplies
no permission for paid model runs; obtain any needed authority separately.

For initial construction, present the requirements and early code without later
findings. For repair, present one admitted finding and its contemporaneous evidence.
Freeze the first completed candidate before exposing withheld sibling failures
and required-valid controls. Do not permit intervening repairs before scoring that
candidate. Distinguish a genuine submitted candidate from a timeout or unfinished
experiment. Repeated samples are trials, not an opportunity to select only the best.

Use the same task route and acceptance endpoint in all arms. First-candidate
assessment is separate from later repair/closeout cost. Any qualification phase
uses the same production review inventory, frozen subjects, resets, recovery,
and convergence rules in every arm; changing those rules is a different experiment.

## Assess the software, not the performance of a method

| Observation | Evidence and interpretation |
|---|---|
| Required behavior | Independent source-derived checks and argument; distinguish bounded tests from a construction proof. |
| First-candidate generalization | Withheld sibling operations/compositions, not only the originally supplied example. |
| Required-valid preservation | Valid retries, failures, continuations, and other source-required behavior; rejecting everything fails. |
| Construction strength | Actual admission, permitted-transition preservation, law implication, and sanctioned-path coverage at the declared domain and evidence strength. |
| Responsibility removed | A source-supported future producer, consumer, or extension no longer needs the targeted independent decision; relocation or a named type is insufficient. |
| Calibration | Appropriate direct corrections and preserved adequate designs; spurious allegations do not induce production changes. |
| Total work | Implementation, investigation, all failures and attempts, validation, migration, and qualification under comparable guarantees. |

Score the entire accepted task. Do not use fewer findings, a clean streak, smaller
diffs, more abstraction names, more skill invocations, or compliance with a
particular reasoning order as substitutes for correctness. Do not count a shared
producer/checker mistake as independent confirmation. Keep safety, completeness,
progress, and preservation distinct where the task requires them.

Report per-task and per-trial outcomes with uncertainty and failure details before
aggregation. Assess quality before cost; an inexpensive but weaker result is not
an efficiency gain. Fix the practical improvement and regression criteria before
the run rather than changing the rubric to fit the candidate. Do not infer a
universal theorem about coding agents from bounded tasks.

If B wins on materially different untouched tasks without unacceptable regressions,
retain it and use targeted ablations to identify the contributing change. If A or C
wins, investigate simplification or a demonstrated missing capability rather than
append another speculative directive. A tie or insufficient power is inconclusive,
not validation. Keep semantic duplication reduction, package consistency, behavioral
improvement, and general efficacy as separate claims.
