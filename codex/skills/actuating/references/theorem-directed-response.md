# Theorem-Directed Counterexample Response

The response to a counterexample is a consequence of theorem identity, not a
menu chosen from intuition.

## Incumbent theorem projection

Project the current construction theorem ephemerally from exact owner evidence:

```text
accepted law
applicability and comparison domain
invalid-family predicate
semantic interpretation and equivalence
source-derived topology
canonical owner and admission cut
admitted carrier
legal constructors and transitions
producer factorization and bypass closure
required-valid interpretation
compatibility and resource boundaries
proof universe and claim strength
```

Bind every component to its exact source or proof. A prose label, digest over
model-authored prose, or previous session conclusion is not theorem identity.

## Earliest-premise blame

Localize the first false dependency:

```text
law authority
-> applicability
-> comparison domain / invalid family
-> semantic interpretation / equivalence
-> source topology
-> canonical owner / cut
-> carrier
-> constructor / legal transition
-> factorization / bypass closure
-> required-valid interpretation
-> realization
-> proof realization / generated output / artifact binding
-> claim strength
```

Later failures may be real, but the earliest supported premise owns the response.
Severity changes urgency, never theorem identity.

## Same-theorem reproof

Before normalization, attempt to re-establish the exact predecessor theorem while
permitting changes only to:

```text
realization
proof realization
generated output
exact-artifact binding
```

If reproof succeeds, semantic theorem identity is unchanged. Isolated restoration
is the only admissible mutation; semantic owner, carrier, topology, factorization,
or claim-strength changes are dominated. The existing
`actuating/direct-repair-admission` materialization must pass before mutation.

A failed materialization does not prove architecture must change. It leaves the
response blocked until exact evidence falsifies a semantic theorem premise.

## Theorem revocation

Construction normalization requires proof that same-theorem reproof is
impossible because a semantic premise is false or incomplete. Revoke the
predecessor theorem before invoking Metanoetic or Universalist, name the failed
premise, and require the successor to prove:

```text
T0 cannot establish the accepted law
T1 changes the legal semantic state space
T1 excludes the supported invalid family
required-valid behavior remains admitted
every sanctioned path factors through T1 or has an owned residual
```

Normalization never follows merely from acceptance, recurrence severity, a
failed restoration packet, or lack of a convenient local repair.

## Derived dispositions

```text
inapplicable / already excluded / duplicate / unentailed
  -> no-current-liability

missing law or risk authority
  -> authority-required

same theorem re-proves and direct-repair admission passes
  -> isolated-restoration

semantic theorem premise proved false
  -> construction-normalization

only weaker bounded theorem supportable with authority
  -> claim-narrowing-or-containment

owner explicitly accepts unresolved liability and closure consequence
  -> explicitly-deferred

relation or proof remains unknown
  -> blocked
```

The labels are outputs of the proof, not a checklist from which the agent chooses.

## Live owner-source frontier

Before response selection, every live relevant owner source must have one current
disposition:

```text
folded
proven non-current
unavailable -> evidence horizon incomplete
```

Owner sources include CAS, provider review, tests, incidents, migrations,
repository-native verifiers, and the Review Fold counterexample corpus. A live
provider finding absent from Review Fold keeps mutation and clean credit closed.

## Minimum sufficient semantic delta

Compare candidates against one constraint set:

```text
exclude the supported invalid family
preserve required-valid behavior and observations
honor compatibility and resource boundaries
cover every sanctioned path
supply the required proof
```

A same-theorem candidate satisfying the constraints dominates a theorem-changing
candidate. After theorem revocation, use Actuating's constructional-dominance
order, then prefer the smallest semantic premise delta. Source line count is only
a later realization-cost tiebreaker.

## Falsifiers

Delete or narrow this mechanism if watched sessions merely emit theorem prose
without changing route selection. It earns permanence only when:

- high-severity realization defects actually use isolated restoration;
- low-severity owner or topology defects still revoke and normalize;
- normalization never begins before same-theorem reproof is disproved;
- missing provider, test, incident, or verifier evidence keeps the cut open;
- topology omissions stop becoming assertion accumulation; and
- smaller same-theorem candidates defeat unnecessary architecture changes.
