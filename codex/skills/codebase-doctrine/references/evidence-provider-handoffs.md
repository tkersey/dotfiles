# Evidence Providers

Codebase Doctrine owns analysis, doctrine induction, and context rendering.
Providers supply bounded evidence; they do not become competing doctrine owners.

## `$codebase-archaeology`

Use an existing architecture map as provisional descriptive evidence when it can
save repeated repository orientation. Recheck any fact that becomes
route-changing, normative, or proof-bearing.

Archaeology discovers and maps. Doctrine adjudicates and compresses.

## `$seq`

Use query-only session, tool, token, memory, and orchestration evidence when
agent-history behavior matters.

Preserve:

- corpus and denominator;
- query and time window;
- contamination from prior generated doctrine;
- exact provenance;
- uncertainty and missing sessions.

Mention frequency is not governing law.

## `$negative-ledger`

Query or export current canonical failed-route evidence.

Only a complete current projection with applicable scope and an unsatisfied
reopening criterion may create durable route exclusion. Fuzzy similarity and one
failed attempt remain advisory.

## `$retrace`

Use bounded replay when a consequential historical architecture, authority, or
proof decision has incomplete visible rationale.

Classify replay evidence as historically explicit, trace-inferred,
replay-consistent, counterfactual-stable, or hindsight-informed. Replay remains
evidence. Current code, current authority, current observations, and current
proof govern present doctrine.

## `$grill-me`

Use for material user-owned judgments that repository evidence cannot choose,
such as target posture, compatibility policy, accepted risk, persistence, or
which normative branch to authorize.

Do not ask it for discoverable repository facts, implementation design, or
repository laws.

A pending user judgment does not stop descriptive research. Continue learning
and preserve the normative branches. Stop only the conclusion or effect that
would require choosing among them.

## Provider acceptance

For any provider output ask:

```text
What exact question does this answer?
What repository state and scope does it describe?
Is it fact, inference, history, or user authority?
What current evidence could contradict it?
Does accepting it change doctrine or only supporting context?
```

Reject stale, wrong-scope, acknowledgement-only, unsupported, or
self-referential material.
