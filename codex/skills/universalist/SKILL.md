# Universalist

## Mission

Recognize when current code is a literal, partial, degenerate, distributed, or
lawless instance of a more general law-bearing pattern, then derive the smallest
effective owned boundary for the current context.

Category theory is a hidden recognizer, not an output requirement.

## Common path

Work on one current context, one owned boundary, and one architectural axis.

1. Bind the current owner, admitted inputs, operations, observations,
   compatibility obligations, effects, resources, and proof surface.
2. Recover the carrier, operations, laws, counterexamples, and residual checks
   already implicit in the code.
3. Decide whether repeated implementations are independent cases or a
   distributed realization of one more general pattern.
4. State the ordinary repository-native candidate first.
5. Compare only materially different moves:
   `preserve`, `restrict-domain`, `strengthen-owner-or-representation`,
   `factor-or-generalize`, `quotient`, `ablate`, or `obstruct`.
6. Nominate the smallest candidate that makes illegal composition or invalid
   state unrepresentable where the host permits.
7. Give the observation-preserving transition, owner of every residual runtime
   check, governing law, falsifier, proof obligation, and invalidation trigger.
8. Return an obstruction rather than inventing correctness the current evidence
   cannot justify.

A more abstract candidate does not dominate merely because it is more general.
It must reduce duplicated law, ownership ambiguity, invalid states, or proof
surface in the actual context.

## Actuating composition

Inside `$actuating`:

- nominate one candidate version;
- do not select or reopen the Construction;
- do not grant mutation;
- do not turn accepted counterexamples into an architecture decision;
- return `candidate`, `preserve-incumbent`, or `obstructed` with evidence.

Actuating alone adjudicates the nomination and authors the current Construction.

## Guardrails

- Do not replace repository evidence with category names.
- Do not create a boundary when the incumbent already owns the law exactly.
- Do not broaden the admitted domain merely to make an abstraction elegant.
- Keep construction, interpretation, validation, migration, and proof owners
  explicit.
- Preserve required observations and compatibility; name every intentional
  retirement.
- Stop when another abstraction would add vocabulary without changing the
  boundary, law, owner, proof, or falsifier.
