# Assay workflow probes

These are authored acceptance cases for this package, not executed model
results, a required runtime suite, or a new assessment policy. Give tested
agents raw task artifacts rather than the expected answers below. Keep
candidate identities, available evidence, and task authority fixed.

## Routing and disclosure

| Request | Expected ownership or read path |
| --- | --- |
| Does this evidence establish that the delivered change preserved the required behavior? | Assay kernel; comparisons reference when comparing successors |
| The grader passes both records, but did the requested operation occur? | Assay kernel and evaluator reference |
| Why did changing this skill's wording alter tool selection? | Cybernating source investigation |
| Implement this accepted parser change. | Implementation owner; no mandatory Assay campaign |
| Run the existing test command and report its terminal result. | Direct runner use when interpretation is already adequate |
| Remember what this repair teaches us for future work. | Learnings; reuse an existing sufficient assessment |
| Use Assay, but no Assay executable is installed. | Assess native evidence; no invented invocation or installation |
| An installed compatible CLI can evaluate the supplied bundle. | Read CLI reference and installed help; preserve its output scope |

A common-path assessment must finish from the kernel and task artifacts.
Conditional comparisons and evaluator assessment must not require reading the
other route. Always-required authority and stopping rules remain in SKILL.md.

## Decision probes

| Raw case | Required distinction |
| --- | --- |
| A passing smoke check covers one required input; the delivered artifact fails another | Refute the broader artifact claim using the actual missed obligation |
| The same implementation satisfies a different accepted contract | Preserve the legitimate no-change outcome |
| Equal aggregate scores hide different failed obligations | Report the relevant preservation difference |
| A repair rejects a required input | Reject the restrictive repair |
| A different representation preserves every required observation | Accept the valid alternative |
| Required checks pass while instruction attribution is unavailable | Permit bounded qualification and leave attribution unresolved |
| Four required reviews complete; a fifth is interrupted | Do not construct five completed clean reviews |
| An interrupted run already observed a prohibited effect | Retain that counterexample; leave other unfinished checks unresolved |
| A timeout violates a required deadline | Refute the deadline claim without inventing another failure |
| A result file concerns earlier candidate bytes | Do not apply it silently to the current subject |
| Equally applicable reports disagree about the same effect and no authoritative observation resolves them | Preserve the conflict and leave the affected claim unresolved |
| A task accepts a declared threshold with observed case failures | Apply that rule; do not invent perfect-score acceptance |
| Final messages match but authoritative effects differ | Identify missing observational discrimination |
| The accepted rule concerns ownership, not runtime output | Assess the artifact and rule without inventing a runtime crash |
| A completed comparative batch has insufficient evidence for population equivalence | Keep the stronger claim unresolved |
| Required artifact evidence is complete; another optimization is possible | Finish the bounded assessment |
| A candidate edits the evaluator to always pass | Preserve the accepted assessment identity; assess the changed evaluator separately |
| Comparing two reports exits 0 while the candidate is refuted | Treat operation success and candidate fitness separately |

## Existing artifact controls

The sibling `actuating/tests/test-review-action-fixture.mjs` exercises a
bounded codec evaluator, including valid alternative representations, rejected
required inputs, changed protected task inputs, unavailable execution, and
preservation across successors. Run it only as an authorized package-validation
fixture. Its success establishes those fixture checks, not this skill's live
activation, causal benefit, or general efficacy.

For a live probe, supply an isolated subject prepared by the existing fixture
and the unchanged accepted Goal. Retain preparation choices with the evaluator;
do not reveal control names, expected results, or the other arm. Freeze the
subject and independently verify its observations. Keep inference/model
identity, context exposure, and any isolation limits explicit in the resulting
validation account.
