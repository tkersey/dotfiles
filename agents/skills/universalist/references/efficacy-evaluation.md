# Universalist efficacy evaluation

Use this reference only while tuning or auditing Universalist, not during ordinary
semantic work. Evaluate the construction produced, not visible theorem names,
invocation frequency, reference counts, or compliance with a preferred encoding.
Authored fixtures and static checks do not establish behavioral efficacy.

## Bind the evaluated subject

Every result identifies the repository and immutable state, Universalist commit
and source fingerprint, model and effective instructions, receiving workflow and
companion versions, tools, budget, and session/root-lineage identifier. Quotient
worker continuations into their root lineage; nested decisions are not independent
trials. Do not combine materially different versions into one efficacy rate.

Bind actual loaded files, not only a version string. Before replay,
`routing-evaluation-cases.json.skill_fingerprint` must match `decision-contract.json`.
The unchanged representation corpus's `skill_version: 17.8.0` records its authoring
baseline, not a later replay result. Historical receipts and measurements remain
attributed to their original sources. Record missing or truncated effective skill
metadata separately from a behavioral failure after successful loading.

## Routing and discovery are different measurements

Use the routing corpus plus independently selected repository holdouts. Distinguish
true activation, false activation, missed activation, correct nonactivation,
preservation resolving a live question, and silent reuse of a settled construction.
Sample nonactivated semantic tasks independently; precision among activations alone
does not establish recall. Include first-use derivation, internal algorithms behind
fixed interfaces, transformations and proof questions without a named boundary
change, distributed laws, and fired invalidators.

Keep mechanical controls: unchanged verification, formatting, publication, landing,
mechanical rebasing, an exact already-derived repair, and settled realization with
no unresolved semantic question. Neither a public interface nor one unchanged owner
settles every internal algorithm. Conversely, inventing hypothetical capabilities
or repeated no-op inquiry is not discovery.

## Prompt-dependence comparison

The main change in version 18 is generative inquiry before a named defect, owner,
axis, typed hole, or completed challenger. Compare the exact pre-change policy and
the revised policy in a controlled two-by-two design:

```text
                         ordinary task prompt       task + targeted hint
pre-change policy        old/unhinted               old/hinted
revised policy           new/unhinted               new/hinted
```

Keep task requirements, repository evidence, model, tools, budgets, and non-target
instructions fixed within a contrast. Start independent runs from the same state;
a hinted run must not inherit an unhinted solution. The hint names a relevant
mathematical perspective or representation question, not the answer or a relaxed
requirement. Control run order and repeated sampling; report variation and sample
size rather than treating a single success as a general effect.

The desired result is better unhinted construction quality and a smaller quality
gap to the hinted condition. A smaller gap caused by degrading hinted performance
is not improvement. Report the four outcome distributions, failures, resource use,
and uncertainty; do not collapse correctness and cost into an unexplained score.
Where no credible target hint is known, retain the ordinary-prompt holdout and do
not invent an oracle hint merely to fill the matrix.

For the end-to-end policy contrast, include the matching root mandate, metadata,
and receiving-workflow adapter changes on each side. Attribute any result to that
bundle. Separately hold companion instructions fixed or use focused ablations to
isolate description/routing, generative common-path reasoning, reference disclosure,
and provisional-formulation handoffs. Disclose coupling instead of crediting every
gain to one sentence. A skill-load failure and a missed derivation after loading
require different repairs.

## Paired contribution ablation

Retain the existing A/B/C comparison with the same accepted evidence and blinded
output evaluation:

```text
A. No Universalist
B. Generative common kernel only
   task and requirements + provisional formulation + bidirectional mathematical
   inquiry + native comparison + claim-appropriate evidence and authority
C. Full Universalist
   the same kernel + question-selected recognition/domain algebra/theory references
   and relevant registered or unregistered constructions
```

Generative reasoning belongs in B as well as C. Do not remove it from B and then
attribute its value to the reference corpus. To isolate the generative-policy
change, compare the exact pre-change and revised kernels separately. Keep all
non-target instructions and evidence fixed and conceal condition labels from the
artifact evaluator.

`B > A` can support a kernel contribution; `C > B` can support incremental reference
or advanced-construction value. `C == B` with unnecessary machinery rejected is a
valid protective result, not evidence that a larger card inventory is needed.
A useful derivation can disappear into an ordinary native implementation. Neither
`UNI-CANONICAL` nor `derived:<name>` is an efficacy metric or proof-strength upgrade.

## Artifact-level discrimination

Keep routing `cases`, `artifact_cases`, and `workflow_cases` distinct in
`routing-evaluation-cases.json`; include the separate representation corpus.
Present only the scenario and authorized requirements to the agent. Expectations,
preferred examples, falsifiers, and scoring criteria are evaluator-only. Accept
any adequate lawful realization, not a particular theorem name or fixture syntax.
Use independent repository holdouts beyond the worked examples; the compositional
accounting example in the instructions is a training example, not a blinded holdout.

Evaluate the actual artifact and argument for:

- preservation of required-valid behavior, observations, and permitted continuations;
- exclusion of invalid states and bypasses, legal composition, and owner correctness;
- authority, effects, failures, compatibility, complete migration, and residuals;
- justified correspondence, applicable laws/non-laws, falsifiers, and proof strength;
- removed obligations or work, native simplicity, caller burden, and resource cost.

Also record unsupported claims, irrelevant reference exposure, speculative scope
expansion, duplicate reports, unnecessary frameworks, and premature completion.
Lower cost cannot compensate for a missing requirement. Equal outputs on samples
do not establish representation independence or effects preservation. More thought
or less code is not automatically a dividend.

The routing corpus retains all earlier cases and adds first-use synthesis without
an incumbent, open algorithms behind accepted interfaces, semantic oracle design,
theory-led inquiry before a candidate, unlisted constructions, and mechanical and
scope controls. Artifact cases include prefix-accounting summary derivation and
its net-only, order, underflow, and unchecked-carrier false friends. The general
argument, finite model evidence, and actual host realization remain separate.

Include negative mathematical controls: multiplicity versus order; current-status
quotients distinguished by later events; a lawful ordinary coalgebra without
finality; observation APIs without a Yoneda claim; phase barriers with ordered
failures; valid pure fusion and invalid effectful fusion; and an adequate existing
implementation that should survive the inquiry. Missing a registry entry cannot
reject an otherwise supported construction, and an unlisted construction cannot
escape its required failure or resource observations.

## Focused representation and algebra ablations

`representation-evaluation-cases.json` retains eight eliminator-first and eight
algebra-derived cases. It is an evaluator corpus, not a test runner or runtime
instruction. The common-path eliminator and algebra questions belong in both B
and C. Remove only the targeted reference guidance for a focused contrast, keeping
other source, evidence, tools, model, budgets, and receiving workflow fixed.

For eliminator-first cases, check reconstruction, inspection, authorization,
identity, sharing, persistence, replay, effect order, failure timing, mutable
captures, repeated consumption, and whole-workload cost. A native fused loop,
ordinary fold retained, or explicit data preserved can each be the right result.
Polymorphic-looking callbacks and finite round trips do not prove parametricity,
initiality, or confidentiality.

For algebra-derived cases, check carrier adequacy, ordered-observation
counterexamples, immediate outputs and residual behavior, law adequacy,
generator/observer coverage, and discovered-law authority. Mined regularities do
not overrule requirements. A unified production interpretation must not erase an
independent oracle. A reference model is optional and valuable only through its
connection to the required semantics and discriminating evidence. Retain existing
caller-contract/information-hiding guidance while isolating ADD changes; hold the
receiving workflow version fixed or report its contribution separately.

## Workflow and decision-sufficiency ablations

Keep contract repair separate from procedural ablation. Use immutable repaired
baseline and candidate sources under identical evidence, model, tools, budgets,
and companion instructions. Existing workflow cases cover incomparable adequate
candidates, claim-scoped obstruction, available evidence versus unavailable
authority, a grounded third candidate, multi-seam completion, and Actuating
presentation and authority. New cases supply a first-use problem without an owner
or typed hole and an Architectonic question with a provisional formulation.

Inspect actual actions and artifact coverage. A nomination may revise a model-owned
formulation without selecting the receiving workflow's target, authorizing an
experiment, breaking a review freeze, editing in read-only mode, or allocating
standalone durability. Mathematical inquiry is not another review lane. Preserve
required evidence while omitting duplicate report headings; a smaller report must
not hide an unfinished caller migration or unresolved premise.

Use focused contrasts for reference gating, candidate quotas, packet presentation,
first-witness stopping, and available-evidence continuation before attributing a
bundled gain to one change. Fewer headings cannot compensate for weaker proof.

## Reference-depth and claim consistency

These nine audit-only scenarios exercise the 18.0.1 corrections. They supplement,
not renumber or relabel, the existing JSON corpora. Keep task requirements and
independent deciding evidence fixed while comparing the root-only condition with
applicable card/mechanics disclosure, and the explicit-team path when authorized.
Bind all loaded bytes and source commits. Vary disclosure separately from policy
version and card membership; disclose unavoidable coupling. Do not load the whole
corpus or expose this evaluator guidance to the agent merely to manufacture a test.

| Scenario ID | Ordinary task and relevant disclosure | Required discriminator / control (evaluator-only) |
|---|---|---|
| `evidence-not-nonexistence` | Decide whether a decoder can realize required behavior; consult the artifact catalogue and, in the team condition, its packet contract. | Uninspected available code is inspected; unavailable evidence stays unresolved. A genuinely information-losing fixed projection has a scoped impossibility argument. Neither a failed attempt nor a missing capability alone proves nonexistence. |
| `structure-profile-fidelity` | Verify an ordinary typed pipeline, first-order callback encoding, or ordered effect composition with its selected card. | Establish applicable laws, preservation, effects, and coverage without invented mediation. A separate free/universal claim still needs its actual factorization and uniqueness proof despite a structure default. |
| `checked-value-without-normalizer` | Accept every nonzero integer and preserve its sign and value through the permitted API. | No normalizer is needed. A candidate that applies absolute value is idempotent but violates required observations; a permitted operation producing zero must not retain unchecked trusted status. |
| `transparent-shared-coordinate` | Combine immutable `(tenant,x)` and `(tenant,y)` values while preserving both projections and admitting every matching pair. | A transparent `(tenant,x,y)` is admissible, as is any adequate native realization. Mismatched ingress is rejected. Add an identity/provenance-sensitive variant where mere value reconstruction is insufficient. |
| `deferred-map-versus-history` | Delay conversions while preserving the required result and, in a second variant, the exact audit path. | Use the identity/flip reindexing counterexample from the mechanics: extensional lowering can agree while deferred paths differ. Required intensional history must survive separately or in a justified richer model; do not reject useful ordinary deferred maps. |
| `card-membership-invariance` | Verify the same source-bound construction once with a matching retrieval card and once without one. | Catalogue membership must not change the required laws or authority. A supported unregistered construction is admissible; an unregistered effect-changing or unproved construction is not exempt. |
| `composite-interaction-proof` | Verify a derived pipeline whose stages each have valid local arguments, with a required end-to-end effect trace. | Check their interaction and interpretation, not only component certificates. Include a lawful composition and a variant whose fusion/reordering violates the trace. Do not require exactly one card for either subject. |
| `encoding-aspects-preserved` | Characterize a law implemented across modules through a shared observation, valid for immutable snapshots but not unchecked aliased updates. | Retain distributed placement, observational correspondence, and restricted scope together. A known lawful relation remains lawful without a refactoring dividend; a failed strict law is not repaired by merely naming it lax. |
| `pivot-reuses-owner-evidence` | Assess a category pivot inside an existing Actuating or Architectonic argument, then consult its specialized reference. | Preserve transfer, effect, resource, and proof obligations without adding mandatory reports, mutation, or durability. An explicitly required consumer format remains applicable; a template's existence alone is not authority. |

The positive controls matter as much as the counterexamples. Accept alternative
adequate representations and proofs. The examples embedded in these instructions
are not independent holdouts; derive repository variants that do not reveal the
expected construction, and keep this table and expected outcomes evaluator-only.

A source audit can establish that contradictory instructions were removed. A finite
model can validate its stated equations or counterexamples. Neither establishes
that deeper disclosure preserves agent behavior: that conclusion requires the
paired runs and their actual artifacts/actions. Report correctness and authority
regressions alongside changes in unhinted quality, resource use, and reference cost.
Do not count a larger report, card match, or statement of a law as a passing result.

## Corpus evolution and result reporting

Freeze new construction-card inventory until repeated paired cases show a concrete
incremental artifact or proof dividend. This maintenance policy neither disables
existing cards nor restricts inquiry to listed mathematics. A retained unregistered
construction uses the same correspondence, hypotheses, effectivity, discriminator,
and native-comparison standards. Attribute its mechanism as `derived:<name>` only
when material; no card addition is required to use it.

Record the task/question, immutable subject, provisional and resulting formulation,
comparison, material consequence, mechanism, artifact or scoped obstruction,
falsifier, invalidators, and actual evidence. Reuse existing evaluator records;
this is not a runtime packet or receipt requirement.

Report routing precision and recall, unhinted artifact quality and hint dependence,
kernel contribution, and incremental reference/mechanics value separately. Include
sample size, uncertainty, failures, regressions, and resource use. Distinguish:

```text
source/JSON/link validation
newly authored evaluation cases
finite witness checks and their explicit domains
actual paired agent runs and immutable evaluated policies
host performance measurements and workload
```

The corpus remains `authored_not_model_replayed` until separately attributed runs
exist; do not relabel old cases or historical results as freshly validated by the
model. A successful static check or finite countermodel does not show that an agent
discovered or implemented the design. No model-efficacy, latency, or performance
gain is established merely by publishing this policy change. No runtime gate,
new evidence store, or executable test framework is introduced.
