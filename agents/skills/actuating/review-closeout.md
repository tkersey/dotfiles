# Review-epoch immutability and evidence acquisition

## Review-epoch immutability and evidence acquisition

Read [review-contract.md](references/review-contract.md). A review epoch opens on
the first review request against an exact locally proved `reviewable` head. While
open, freeze that subject and forbid successor mutation.

A material current entailed finding invalidates the candidate and all review
credit immediately. It does not request a patch. Complete the initial inventory
of six changeset-wide lenses and all six lenses for every selected file against the frozen
head: parallel siblings are non-cancelling; serial mode continues all remaining
initial requests for evidence only. Required request-local recovery is part of
the barrier. Fold the complete cut before closing the epoch.

A material later standard-confirmation finding stops further confirmations.
Fold it and already-live required owner observations; do not launch another
auxiliary wave on the invalidated head. A clean epoch closes after convergence.
Outside an open review epoch, review is not a prerequisite for implementation.

After closing an invalidated epoch, carry its outcome into the
[progress assessment](recurrence.md#progress-before-another-iteration) before
selecting a successor. Count the closed epoch once; its requests and clean
confirmations are not separate repair rounds. Reset review credit as required
while preserving the history of unsuccessful approaches.

## Self-review while reviewers are running

While required reviews are in flight, use otherwise available time for
read-only self-review of their exact frozen subject. Start from the accepted Goal
and actual code. Challenge consequential assumptions and proof choices made during
implementation; seek concrete counterexamples to required behavior or the
construction's claimed guarantees.

Continue the inquiry across waiting intervals. Prefer unexamined, material
questions over repeating completed checks. Collect review results, perform required
recovery, and dispatch required reviews promptly. Do not prolong the epoch merely
to finish a self-review pass; when no useful falsification target remains, wait.
This supplements required pre-review proof; discovering missing mandatory proof
retains the existing reviewability-invalidation rule.

Route self-discovered candidate findings through Review Fold as they arise,
preserving exact-subject and self-review provenance in the existing handoff.
Adjudicate them under the same [counterexample admission](../review-fold/SKILL.md#counterexample-admission)
as other findings; a suspicion alone is not an admitted violation. An admitted
current material finding entailed by the Goal invalidates the candidate and all
review credit even when the executor returns clean. Complete the initial frozen wave, or
stop new confirmations and fold already-live required evidence, under the existing
phase rules. Adjudicate discovered material evidence before claiming convergence.

Preserve the frozen subject and reviewer inputs. Defer successor changes, including
test edits and mutation experiments, until the epoch closes. Self-review supplies
evidence; it provides no executor receipt, independent confirmation, or clean credit
and adds no required review lane or pass-completion gate. Existing route and
corpus-write authority still govern every handoff.

## Review and closure

The changeset-wide inventory remains standard, soundness-skeptic, footgun-finder,
invariant-ace, complexity-mitigator, and fresh-eyes. In default native Codex mode, standard
is Codex's native review with no custom Actuating instruction file or argument.
Explicit subagent mode uses the pinned Codex rubric under
[subagent-reviews.md](references/subagent-reviews.md). Auxiliaries retain their
exact checked-in lenses in both modes; none substitutes for standard.

Before dispatch, inspect the diff and select up to three files with significant
changes to non-test code under
[Focused file reviews](references/review-contract.md#focused-file-reviews).
Give each selected file all six lenses as independent reviews in the same initial
wave: up to 24 requests across the changeset and three files. File focus anchors
the inquiry while allowing relevant cross-file evidence. File standard uses
general best judgment with custom focus instructions; subagent file-standard also
receives the pinned rubric. Neither earns changeset-standard convergence credit.
Each file auxiliary receives its exact unchanged lens plus
the file scope. Every reviewer continues beyond the first finding; fold the full
initial batch before choosing a successor. File reviews are initial-only.

Only a completely realized, locally proved candidate is `reviewable`. Require
five consecutive distinct changeset standard cleans from the selected executor
on one unchanged head under one bound review policy,
each admitted by [Review-credit admission](references/review-contract.md#review-credit-admission).
The initial credited standard counts as one and the next four run serially. All
five changeset auxiliaries and every selected file/lens pair must be terminal, adjudicated,
and credited for their own requested obligations before later confirmations.
Later confirmations remain changeset-wide. File credit never advances the changeset
standard streak or completes any other scope/lens obligation.
An acknowledged limitation or raw verdict is not that decision.
Use the same dispositions for counts and user/PR completion statements. A material
finding or head change resets all credit. Reviews falsify; they do not prove
soundness by failing to find a bug.

Read [closure.md](references/closure.md). `implement` ends at local completion;
publication and convergence belong to bare Actuating and `review-closeout`.
Closure requires exact Git, verifier, selected-executor, and Ship/provider facts as applicable.
An unresolved accepted liability, unauthorized strengthening, missing required
proof, or unowned residual cannot become unqualified `complete`. Complete the
object-level task before optional learning or memory capture.
