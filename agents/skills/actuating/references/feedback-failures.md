# Feedback-generated failures

Use during existing counterexample adjudication/causal compilation when a witness
under consideration involves correction, accumulation, delayed effects, or apparent
compliance that fails the accepted purpose. Reuse the Goal, witnesses, Working Set,
and discriminator. This reference adds no review lane, receipt, schema, experiment
permission, or mandatory diagram. Actuating remains the causal and selection owner.

## Follow the response back to its cause

Check whether otherwise lawful operations compose into a harmful loop: a timeout
causes a retry, which increases load and latency, which causes further timeouts.
An individual operation need not violate its local law. Identify the system
obligation that the interaction fails; do not silently broaden the original law.

Trace only the relevant accumulated state, inflows/outflows, observations, action
authority, delays, and corrections already in flight. Include the response of an
external actor when it can change the explanation. Distinguish a demonstrated
coupling from mere recurrence, fixed capacity shortage, or an isolated defect.
Use the predicted temporal response as the existing sibling/domain discriminator.
Native traces and source arguments can suffice; samples do not prove stability.

Feed a live ownership, representation, or composition decision to the existing
architecture path. A wider explanation can justify a small admission or policy
change. Do not require a malformed constructor, merge all actors, or invoke
Universalist solely because a loop exists.

## Distinguish the trap before strengthening the remedy

| Supported mismatch | Deciding question | Consequence within current authority |
|---|---|---|
| Perfect compliance, failed purpose | Can the current rule be satisfied while a source-backed outcome fails? | Distinguish a wrong proxy/model from missing enforcement; correct a model-owned proxy with independent evidence, or return a required-goal change to its authority. |
| Apparent compliance through evasion | Does the rule induce behavior that defeats its purpose while satisfying its surface? | Inspect the rule and induced incentive before adding enforcement. Do not infer intent from a disappointing result. |
| Stronger intervention, same unwanted state | Does the intervention induce a compensating response from another actor or controller? | Compare removing the induced conflict or amplification; repeated failure alone does not establish policy resistance. |
| Growing dependence on repair | Does compensation hide a widening mismatch or degrade maintenance of the rightful owner? | Restore that capability or durably reassign responsibility before retiring support on which valid behavior depends. |

Keep the accepted Goal fixed. A required review count or procedure remains required
even when it does not establish a separate outcome claim. A checker correction
needs the existing source-grounded oracle argument; changing expectations to make
a candidate pass is not goal repair. Use Review Fold's current authority and
admission classifications, not this table as another disposition taxonomy.

## Retire compensation by causal role

Software does not atrophy merely because it is unused. Require evidence of growing
protocol drift, suppressed defect information, expanding exceptions, or neglected
maintenance before diagnosing burden shifting. Repeated calls to a correct shared
serializer, stable supervisor, or required trust-boundary validator are not such
evidence. Preserve independent verification and distinct runtime defenses.

For a repair layer masking producer drift, compare restoring the producer's
contract with deliberately moving that responsibility to a suitable owner. Show
which capability and feedback survive the transition. Removing the repair first
can expose the very failure it currently contains; retire it only after its live
obligation is discharged. Count a verified durable reassignment as a valid outcome.

## Change the intervention when its mechanism warrants it

When successive adjustments fail for a supported feedback reason, consider a
change to amplification, information access, policy, or ownership before increasing
the same correction. A bottleneck's cost or delay may itself regulate demand;
removing it can change the conditions that supported the old explanation.

Route reconsideration of the explanation, proxy, or assumed intervention through
the existing Metanoetic activation path. Reuse an applicable activation; add no
reference-specific pass or report. Treat leverage categories as
candidates, not a ranking: a parameter change can be the best intervention.
Compare consequence, evidence, required-valid preservation, migration, and cost.
Changing an authorized outcome or resource ceiling still needs its source authority.
Stop this inquiry when another causal layer cannot change the selected response,
or return the specific unresolved premise and discriminator.
