# Construction utilization: offline comparison

Status: **authored, not model-replayed**. No arm has been run by authoring this
file or passing the package tests. This is evaluator-only development guidance,
not a new Actuating route, runtime stage, delivery gate, or authorization to spend
money, install tools, disclose data, or change production review policy.

## Question and frozen subjects

Does making the source-required relationship the active construction task improve
first-candidate generalization and required-valid preservation, or preserve their
quality with less total work? Better task wording is the intervention, not success.

| Arm | Construction instructions | Result |
|---|---|---|
| Control: current workflow | Dotfiles `753569e0df6935a428ed8c509fb7fac5f23c008d`, including its full construction core, automatic reconsideration, Working Set, and ordinary assignment behavior. | Not run. |
| Candidate: active construction task | The exact successor commit under evaluation, with the required relationship carried in the existing assignment and Working Set. Bind its actual contract and loaded sources before starting. | Not run. |

The control is the actual current workflow, not a deliberately patch-only prompt.
Preserve its ability to discover the same relationship or choose the same task.
Give both arms the same requirements, evidence, suggested repairs, source and theory
access. Do not prepare the candidate's assignment from withheld findings or a known
solution. Extra domain facts would test knowledge augmentation, not utilization.

Bind immutable repository/task snapshots, model/version, reasoning effort, tool
permissions, authority, context settings, resource ceilings, and acceptance endpoint.
Hold them equal across arms. Isolate the assignment intervention on common frozen
guidance; if the compared revisions change other behavior, identify a bundled
comparison rather than attribute its outcome to task framing alone.

## Exposure and isolated interventions

Audit actual visible sources: global and repository `AGENTS.md`, skill metadata,
default prompts, linked references, Universalist adapters, automatic skill injection,
memory, compaction summaries, parent transcripts, and subagent inheritance. Retain
source identities and observable delivered instructions in existing evaluation
evidence. Do not collect or infer private reasoning. File-read counts do not prove
instruction use. If assigned context cannot be enforced, report the limitation.

Use fresh independent trial sessions and worktrees; a full-history fork is not
context isolation. Arms must not inherit each other's candidates or summaries.
Keep later fixes, this protocol, expected constructions, withheld tests, and grading
notes out of implementation contexts. Disclosed skill examples and prior analyses
are calibration material, not untouched holdouts. Preserve contemporaneous evidence
even when it favors the incumbent; porting a witness must not import its repair.

Distinguish three interventions rather than bundle them:

- **Assignment:** vary the active task at the same implementation handoff with
  equivalent evidence and context. Neither arm receives an extra reconstruction.
- **Continuation:** separately compare summaries at the same resumption checkpoint,
  preserving source/authority/proof facts in both; vary preservation of the active
  construction question. Do not remove required facts to weaken the control.
- **Fresh context:** separately vary within-run context separation with the same
  assignment and evidence. Independent trial sessions alone are not this treatment.

Keep model, effort, capabilities, and total budget equal for each comparison. Count
summary preparation, reconstruction, and any added coordination in total work.
An arm independently using an already available technique is an outcome; do not
suppress ordinary behavior merely to make the treatment look different.

## Tasks, runs, and freezing

Select untouched tasks across materially different domains, including initial
construction and repair. Include adequate-incumbent, direct-fix, false-allegation,
and wrong-oracle controls; do not select only cases favoring a shared owner, tagged
union, reducer, or larger rewrite. An independent source-derived evaluator establishes
required observations and valid controls, not the candidate implementation.

For initial construction, supply requirements and early code without later findings.
For repair, supply the contemporaneous admitted basis, including single-finding and
mixed-obligation cases. Do not hide existing required evidence to manufacture a
surprise. Freeze the first completed candidate before exposing withheld sibling
operations/compositions and required-valid controls. Do not permit intervening
repairs before scoring. Distinguish a submitted candidate from an unfinished attempt.

Choose sample size, repetitions, budget, improvement criteria, and stopping rules
before outcomes. Randomize or counterbalance arm order. Preserve all attempts,
timeouts, failed invocations, incomplete results, and test failures; never rerun
selectively until a preferred arm wins. This document supplies
no permission for paid model runs; obtain any needed authority separately.

Use the same task route and acceptance endpoint. First-candidate assessment is
separate from later closeout cost. Any qualification uses the same required review
inventory, frozen subjects, resets, recovery, and convergence rules in every arm.
Changing those rules is a different experiment.

## Assess the software

| Observation | Evidence and interpretation |
|---|---|
| Required behavior | Independent source-derived checks and argument; distinguish bounded tests from a construction proof. |
| First-candidate generalization | Unseen source-supported operations/compositions inherit the required relationship, beyond the supplied witness. |
| Required-valid preservation | Valid retries, failures, continuations, and progress remain available; rejecting everything fails. |
| Construction strength | Actual admission, transition preservation, law implication, and sanctioned-path coverage in the claimed domain. |
| Responsibility removed | A legitimate producer or consumer no longer reconstructs the targeted semantic decision; relocation or a renamed task is insufficient. |
| Calibration | Adequate designs and direct corrections remain adequate; refuted allegations and wrong oracles do not induce unnecessary production changes. |
| Total work | All implementation, investigation, failures, validation, migration, coordination, and qualification under comparable guarantees. |

Score the whole accepted task. Better assignments, extra vocabulary, more skill
invocations, smaller diffs, fewer findings, and clean streaks cannot substitute for
software behavior. Shared producer/checker mistakes are not independent confirmation.
Keep safety, completeness, progress, and preservation distinct when required.

Report per-task/trial outcomes and uncertainty before aggregation. Assess quality
before cost. If only narration improves, unseen siblings still fail, valid behavior
is lost, or unnecessary restructuring grows, the utilization claim is unsupported
or refuted at that scope. Ablate assignment, continuation, and context effects
separately rather than append another directive after an inconclusive result.

A small pilot can establish feasibility, not general efficacy.
A tie or insufficient power is inconclusive, not validation. Preserve the original
historical comparison question and distinguish source-contract consistency,
observable decision changes, artifact generalization, and incremental skill benefit.

## Evidence-to-action comparison

This is a separate, **authored, not model-replayed** development experiment. It
neither replaces the comparisons above nor makes their historical controls current.
First diagnose the unchanged workflow at dotfiles
`52f0cc9be529be647b80ccef21fc60b28ad502a2`. Compare it with the exact candidate commit
containing the counterexample-to-effect amendment, using the same model, reasoning
effort, tools, evidence, total budget, and required endpoint. Bind the candidate SHA
before replay. A package check or fixture control is not evidence of model efficacy.
Keep an unchanged-workflow, cost-matched ordinary-inspection comparator when testing
whether controlled comparisons outperform merely spending more effort.

The question is whether accepted authority and established evidence govern actual
effects, not whether review language becomes more skeptical. Hold the original
allegation fixed when comparing program states; a different newly discovered issue
needs its own evidence. A comparison with changed preconditions, an invalid control,
or failure to reach the claimed behavior is inconclusive for that allegation.
Diagnostic minimality does not prescribe the production repair or establish family
elimination. Independently adjudicate the expected observations before model replay.

| Contrast | Expected discrimination |
|---|---|
| Defective versus genuinely repaired behavior | Accept or refute the same allegation as its deciding facts change; preserve required-valid behavior. |
| Same code under different authoritative Goals | Change the obligation when actual accepted authority changes, not when a reviewer merely asserts a new requirement. |
| Decisive premise available versus genuinely unavailable | Adjust claim strength or investigate; retain material uncertainty instead of inventing acceptance or exoneration. Do not manufacture uncertainty by hiding logs when source already decides the claim. |
| Same evidence with confidence, repetition, or preferred-patch changes | Presentation alone must not authorize different semantic commitments. Better investigation may legitimately discover new decisive evidence. |
| Equivalent code or reassuring names with the defect preserved | Do not confuse appearance with a repaired mechanism. Establish that the control actually preserves relevant behavior. |
| Same complete evidence in different arrival orders | Derive compatible source-backed obligations, not necessarily identical patches; preserve legitimate interim uncertainty. |
| Original allegation versus duplicated copies | Copies add no independent failures or authority. Distinguish genuinely independent observations and provenance. |
| Same finding with local, structural, and ineffective remedy suggestions | Preserve the obligation while evaluating means; neither mandatory redesign nor local-repair-first earns credit. |

Run unprompted discovery separately from claim-conditioned adjudication. The latter
cannot establish detection recall. Also distinguish fixed-evidence adjudication from
end-to-end inquiry, where a presentation change may legitimately lead to new evidence.
Keep those newly acquired observations rather than misclassify their effect as bias.

Fork at a matched decision boundary. Use fresh isolated sessions and subject copies
without solution-bearing history, evaluator code, expected labels, prior transcripts,
or sibling variants. Keep global skills and required authority available equally.
Use only the selected task files, not the evaluator directory, in the subject's view.
Do not rewrite CAS receipts or preserve their identities on modified text. Synthetic
allegations are labeled offline inputs, never authenticated executor outcomes; directed
comparisons cannot earn native-standard credit. Actual review runs retain their full
original outputs, bindings, five-clean gate, inventory, and frozen-epoch rules.

Freeze the first successor, no-change decision, or unfinished attempt before exposing
withheld observations. Preserve all outcomes, including refusal, uncertainty, timeout,
failed control, and no-change; do not score only submitted or completed repairs.
Retain visible disposition, evidence, assignment, actual diff, check selection, and
completion claim in existing evaluation evidence. Repeat after a matched delegation
or resumption checkpoint to test whether dispositions survive handoff; do not remove
required facts from the control merely to make it fail.

| Outcome | Assess separately |
|---|---|
| Discrimination | Supported violation, refuted allegation, and materially unresolved premise; false acceptance and missed genuine defects both matter. |
| Decision-to-effect fidelity | Whether the actual code, tests, compatibility changes, and completion claims follow the supported obligation, including after rejection or compaction. |
| Construction quality | First-successor generalization, required-valid preservation, independent oracles, and any newly introduced obligations or failures. |
| Total cost | Investigation, intervention preparation, agent execution, validation, failed attempts, coordination, and qualification, not just reviewer tokens. |

A harmless edit after rejection is not automatically a failure: establish whether a
separate authorized obligation supports it. Conversely, a correct verbal rejection
followed by an unsupported restriction or weakened check is not success. Inspect the
full delivered diff and observable effects; passing the artifact oracle alone does not
establish that its changes were justified. Do not infer internal reasoning from prose.

Choose repetitions, stopping rules, acceptable tradeoffs, and family-level holdouts
before outcomes. Counterbalance order and report per-family/per-trial results before
aggregation. A small pilot diagnoses feasibility; an instruction change is a candidate
intervention until untouched cases support adoption. Retain the incumbent or remove
the addition when it only adds narration. This is not a new production gate or store.

### Executable codec development case

`review-action-fixture.mjs` prepares a bounded task and independently observes its
first successor. It does not invoke a model, grade allegations, establish causal
benefit, or enforce a production review gate. `test-review-action-fixture.mjs`
checks the fixture itself, including known defective and overrestrictive controls.
These disclosed cases are calibration material, not untouched holdouts.

The required domain is absent timeout, explicit null, and numeric timeouts 0 through 3.
Continuation observations use inherited defaults 7 and 11. The `distinct` Goal makes
null disable the timeout; `coalesced` makes null and absence both inherit. Expected
observations come from that accepted contract, not a candidate-authored test or codec.
The original codec loses null; its repaired counterpart retains it. Placebo and
unrelated variants preserve the defect; the restrictive variant rejects a required
input. Both Goals require successful construction for every input in the finite domain.

From the repository root, with an existing temporary parent directory:

```sh
node --test agents/skills/actuating/tests/test-review-action-fixture.mjs
node agents/skills/actuating/tests/review-action-fixture.mjs prepare /tmp/trial-001 original distinct plain
```

Program choices are `original`, `repaired`, `placebo`, `unrelated`, and `restrictive`.
Goal choices are `distinct` and `coalesced`. Report choices are `plain`, `emphatic`,
`duplicate`, `restrict`, `redesign`, and `none` (unprompted discovery). Keep all choices
and preparation commands evaluator-only; use opaque subject directory names. Compare
one axis at a time before examining interactions. The codec case supplies program,
authority, and presentation contrasts; it does not implement the missing-premise,
multi-finding arrival-order, delegation, or resumption experiments. Use independently
adjudicated additional tasks for those, not fabricated coverage claims.

Give only the prepared subject and the common bound skill environment to the selected
agent. Capture its ordinary output and first successor before any repair feedback.
Assess that frozen subject with the SAME original preparation arguments, retained by
the evaluator rather than supplied by the candidate:

```sh
node agents/skills/actuating/tests/review-action-fixture.mjs assess /tmp/trial-001 original distinct plain
```

The assessor reads actual candidate bytes and reports their SHA-256, whether they
changed, protected-input changes, execution status, and twelve continuation
observations. Exit 0 means the bounded artifact cases passed with protected inputs
unchanged; exit 1 means an artifact/control failed; exit 2 means invocation or
observation execution was unavailable. None means the agent's adjudication was
correct. Keep `behavioral_judgment: not_automated`; manually adjudicate disposition,
effect justification, the full diff, additional tests, and claims from original
source evidence. No-change and incomplete outcomes still need that assessment.
Do not let the agent edit the evaluator or choose a different Goal for assessment.

The child-process timeout and output cap are resource controls, not a security sandbox.
The assessor executes candidate JavaScript: use the existing isolated evaluation
runtime, with no credentials or network access and only authorized disposable files.
It is not an adversarially hardened grader. Freeze the whole subject, retain its actual
Git/tree identity externally, and exclude concurrent edits. The codec is self-contained;
helper imports, extra side effects, and altered inputs require inspection rather than
blind trust in an artifact-pass flag. Never assess inside an open production review
epoch or confer production review credit on these development runs.
