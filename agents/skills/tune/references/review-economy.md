# Review economy and context experiments

Use only when Tune is explicitly asked to evaluate review policy, shared review
context, or the marginal value of a cognitive intervention. Apply
[agent-performance.md](agent-performance.md) and Tune's existing authority,
measurement and reporting rules. These are selected evaluation recipes, not new
public modes, production review options, startup work, or another evaluator.

Useful requests through the existing interface:

```text
$tune tune Actuating's standard-confirmation yield from existing review evidence;
keep production policy unchanged and do not launch new reviews.

$tune tune the full-history and focused-context Elenctic evaluation variants
on the supplied immutable cases within the explicitly authorized evaluation budget.

$tune tune Metanoetic's activation and decision influence on the supplied cases;
preserve its canonical passage and distinguish outcomes from activation.
```

## Common boundary

An evaluation request does not itself grant paid inference, new-provider data
export, installation, production access, remote mutations, or a budget. Use the
supplied evidence and existing permission. When execution authority, runtime, or
cases are missing, finish an evidence-bound analysis or proposed experiment;
identify the missing execution condition, never manufacture a run or verdict.

Keep the current production contracts unchanged: Actuating's five standard
cleans and five auxiliary obligations, its epoch/reset/proof rules, Elenctic's
full-history seed requirement, and Prove It's selected nine-lens-plus-oracle
gauntlet. Evaluation results earn **no production review, Viewed, thread,
publication, or closure credit**. A prospective variant is not a completed
Actuating or Elenctic run and cannot be used as a fallback for one.

Use existing Tune evidence/reporting, [CAS](../../cas/SKILL.md) for supported
review execution/receipts, and [Seq](../../seq/SKILL.md) for session observations.
Read the owner before its operation. Do not invent CLI switches, fork support,
receipts, agent capabilities, or usage fields. Do not add a review lane, native
mode, mandatory receipt, durable store, or inference service to run these cases.
An evaluation must be separately identifiable from a production request in the
existing task/owner context; do not alter, relabel, or award different credit to
an original owner receipt.

Before execution, bind the exact cases and source horizon, accepted obligations,
base/head and tool/data snapshots, actual model and reasoning configuration,
reviewer instructions, permitted effects, resource ceiling, quality floor,
regression/holdout cases, and deciding observation in Tune's existing working
facts. Preserve current user/model policy; do not assume Astra from this guide or
silently change a Sol default. Policy changes and model changes are separate
experiments. Keep reviewer and implementer model/effort parity where required.

Hold non-treatment variables comparable. Use paired cases and randomize order
where feasible; avoid exposing one arm's findings to the other before independent
results return. Record cross-warming or other interference. Include missing,
failed, timed-out and held results in coverage and cost denominators. Stop at the
accepted budget or a safety/authority boundary, not at the first favorable result.

## Actuating: additional standard confirmations

Read the current [review contract](../../actuating/references/review-contract.md)
for the production baseline. Do not change its JSON, lens prompts, native default
review, or credit rules for this experiment.

| Arm | Evaluation inventory on an unchanged candidate |
|---|---|
| Production baseline | Initial standard plus five auxiliaries; four subsequent standard confirmations, with the existing ordering, adjudication, invalidation and recovery rules. |
| Reduced evaluation | The same initial standard plus all five auxiliaries; no subsequent standard confirmations. This is a six-review evaluation, not production convergence. |

Start with retrospective analysis when complete exact-head owner evidence exists.
Bind each receipt to the actual candidate, model, instructions and review scope.
Adjudicate supported material defects and duplicates under the same accepted
requirements, preferably without exposing the discovering arm to the adjudicator.
Compare the union from the first standard and five auxiliaries with the additional
material defects uniquely contributed by confirmations two through five. Report
which rounds were actually reached: production invalidation may stop confirmations,
and a missing/held result is not a clean review. Do not pool receipts across heads.

This retrospective mask measures observed marginal detection, not a causal
latency saving or proof that omitted calls would never matter. A candidate with
all ten clean reviews contains no positive defect-detection evidence. Include
known-defect and hard negative cases; failures on earlier candidates cannot be
silently transferred to a later unchanged-head denominator.

For an authorized prospective comparison, execute both inventories in isolated
evaluation contexts using the existing supported review interfaces. Preserve
native/default standard review without custom instructions. The reduced arm is
selected by Tune's evaluation assignment, not by overriding an active Actuating
closeout. Preserve freeze, finding adjudication, required proof and recovery
semantics in both arms; never continue repairing one arm while comparing the
other against the original candidate. Repaired successors are separate cases.

Measure supported material defect detection and known-defect misses first,
false findings and completion quality second, then actual end-to-end latency
and resource use. Attribute findings by semantic defect/obligation, not matching
wording or counts of comments. Disclose correlated repetitions, sample size and
uncertainty. Do not infer statistical independence from distinct request IDs.
A critical regression, unassessed gap, or too few positive cases prevents a
non-inferiority claim even when the shorter arm is cheaper.

A production count change requires explicit adoption authority and sufficient
quality evidence. Otherwise return retain-baseline or inconclusive; preserve
all required reviews in normal work.

## Elenctic: full-history versus focused-context seed

Read [campaign preparation](../../elenctic/references/campaign-brief.md) and
[native forks](../../elenctic/references/native-forks.md) before selecting an
available transport. Keep candidate, selected files, concurrency, worker contract,
proof obligations and discussion evidence fixed; change only inherited context.

| Arm | Worker context |
|---|---|
| Production baseline | The qualifying immutable full prepared-history seed required by Elenctic. |
| Focused-context evaluation | Accepted requirements/constraints, exact candidate and selected-file identities, the same source-bound Campaign Brief, and accessible complete supporting sources/discussions, without earlier coordinator exploration. |

Retain accepted instructions that occur outside the brief; do not discard an
obligation merely to shorten context. Preserve established facts versus
provisional hypotheses and source locations. Include the author's strongest
substantive defenses and the complete relevant exchanges, not only accusations.
Keep evidence access the same where possible and disclose any difference.
Neither arm may expose private reasoning, secrets, or unauthorized transcripts.

Build the focused-context seed only with a supported isolated evaluation route.
Record its actual lineage/context and its deliberate nonconformance with the
production full-history requirement. Never forge a native fork receipt, pass it
as a qualifying campaign seed, or silently edit the production campaign contract.
If the runtime cannot create the selected context, report that arm unavailable;
independent tasks or copied summaries are not production substitutes.

Workers perform the same read-only causal investigation and must validate
premises locally. Sibling results remain isolated until reconciliation. Evaluate
cross-file defects, missed obligations, repeated already-rebutted findings,
unsupported agreement with coordinator hypotheses, discussion-update handling,
quality, latency, and observed usage. A later substantive reply can invalidate a
finding without changing the head; preserve observation times and refresh current
evidence under the existing discussion contract.

Measure actual lineage-owned token deltas through Seq's owning token-usage
projection when available. Do not multiply inherited context size by worker count
or sum raw turn/session totals to invent a bill. Distinguish billed/observed usage,
cached input, unobserved usage, and elapsed time; neither shared ancestry nor equal
brief digests proves epistemic independence. Evaluate warm/cold cache conditions
and holdout cases before proposing production adoption.

## Cognitive interventions: activation, influence, outcome

Keep [Metanoetic](../../metanoetic/SKILL.md) and [Glaze](../../glaze/SKILL.md)
canonical passages unchanged unless the experiment explicitly authorizes that
separate treatment. Description relocation, passage replacement, model changes,
and workflow changes must not be bundled into an unattributable experiment.

Use real task decisions: repeated repair, an assumed limit, a distributed law,
an adequate incumbent, and an explicitly requested sensory explanation. Include
routine near misses and shadow failures such as unjustified redesign, unsupported
confidence, manufactured alternative quotas, or treating metaphor as evidence.
See [workflow-probes.md](workflow-probes.md) for selected cases.

Observe appropriate activation separately from a consequential decision delta,
and both separately from validated outcome quality. Useful deltas can be a better
question, representation, discriminator, proof strategy, or removal of an imposed
burden without a code change. Retaining the incumbent or completing an explanation
can succeed; novelty, invocation, vocabulary and report length are not success
criteria. Do not demand a prior challenger, defect, failed local attempt, or
independent reconstruction as an activation prerequisite.

Preserve Universalist's ordinary-first, not ordinary-only, reasoning and
Synesthesia's freedom to discover through sensory representation with literal
accountability. Assess protected behavior and evidence-bound utility rather than
stylistic conformity. Use matched/held-out decisions and blind outcome review where
feasible. Association in historical sessions does not prove causal improvement.

## Report and adoption

Use Tune's existing report; include exact variants/cases, exposure and failure
denominators, quality/defect results, uncertainty, actual time/cost coverage, and
retained/rejected/inconclusive disposition. For zero successful tasks, cost per
success is undefined. Preserve useful evidence without a new mandatory artifact.

A structural check establishes package shape or read-path preservation; it does
not establish activation, independence, defect detection, latency, or model
quality. With no live runs, say so. A proposed policy remains a proposal until
explicitly adopted with its affected owner contracts and regression evidence.
