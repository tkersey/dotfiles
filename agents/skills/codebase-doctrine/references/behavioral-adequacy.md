# Behavioral Adequacy

A doctrine is adequate when it changes future reasoning in the right way. Field
presence, graph closure, identifier shape, or schema conformance cannot establish
that property.

Run these rehearsals before finalizing consequential doctrine.

## 1. Change simulation

Choose three repository-plausible future changes:

1. an extension within the current architecture;
2. a boundary, authority, compatibility, or storage migration;
3. removal of an apparent workaround, fallback, duplicate check, or legacy path.

Using only the rendered doctrine, answer:

```text
What should be inspected first?
Which authority owns the decision?
What must remain observable?
What may vary freely?
Which tempting route should be rejected or treated as suspicious?
What proof is required?
What would reopen the doctrine?
```

Where the doctrine cannot answer a material question, perform the smallest
inquiry that could repair the gap.

## 2. Wrong-model discrimination

Construct the repository's most tempting plausible wrong mental model.

Examples:

- a validator mistaken for an owner;
- a cache mistaken for the source of truth;
- a migration bridge mistaken for the target architecture;
- duplicated validation mistaken for defense in depth when authority is split;
- current implementation order mistaken for a required semantic order;
- historical compatibility mistaken for permanent law.

Ask whether the doctrine clearly defeats that model and points to the evidence
that distinguishes it from the current explanation.

If both remain credible, record governed aporia rather than choosing by cadence.

## 3. Novel-case transfer

Create a case not represented by the historical wounds that produced the
candidate law.

A transferable law should predict:

- jurisdiction;
- owner;
- legal transition;
- forbidden bypass;
- permitted implementation freedom;
- proof burden.

If it only restates known bugs or fixtures, narrow it or keep it as wound memory.

## 4. Ablation

Remove each doctrine item mentally.

Ask:

```text
What plausible future decision becomes worse?
Which wrong route becomes newly attractive?
Which proof obligation disappears incorrectly?
Which freedom becomes obscured?
```

If removal changes no plausible decision, move the item to the evidence appendix
or delete it.

Ablation should shrink the active context, not merely praise every item as useful.

## 5. Drift and invalidation

For every consequential law or authority, name changes that would make it:

```text
false
obsolete
local rather than repository-wide
split across authorities
temporarily suspended by migration
newly contested
insufficiently proved
```

A doctrine without invalidators becomes cargo cult. A refresh without invalidated
claims becomes document maintenance.

## 6. Aporia governance

For each unresolved material tension verify that the doctrine states:

- the competing claims and their jurisdictions;
- current evidence for each;
- unsafe or conditional operations;
- the bounded operating rule;
- the evidence or owner decision that could resolve it.

Unresolved does not mean inadequate when the contradiction is real and future
behavior is bounded.

## Adequacy outcomes

Use ordinary language, not a machine verdict:

```text
Adequate
  The context changes representative decisions correctly, defeats the main wrong
  model, transfers to a novel case, survives ablation, and names invalidators.

Targeted inquiry required
  One or more exact questions could materially improve the doctrine or consumer
  context. Name those questions and the cheapest discriminating searches.

Blocked
  Required evidence or user authority is unavailable and the missing information
  prevents a safe conclusion. State which conclusion remains unavailable.
```

Never claim exhaustive understanding. Stop when additional search is unlikely to
change a material doctrine or consumer-context decision and all material aporia
is represented and behaviorally bounded.
